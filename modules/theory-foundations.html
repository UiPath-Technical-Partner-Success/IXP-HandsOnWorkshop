Foundations: UiPath, DU and IXP

📖 Refresher (optional)⏱ ~15 min readBefore Day 1

🌱 Foundations: UiPath, DU and IXP

⏱ Self-study before the session (~15 min) · Used in every lab, starting with Lab 1

In one sentence: UiPath is an automation platform; Document Understanding (DU) is its framework for turning files into checked data; IXP (Intelligent Xtraction and Processing) is the newer extraction service you will build and tune in this workshop, using a large language model (LLM) that you steer with plain-language instructions.

The platform pieces you will touch

PieceWhat it isWhere you meet it here
Automation CloudUiPath's cloud platform. Your organization has one or more tenants; each tenant hosts services such as Orchestrator, Action Center and IXP.You sign in here and open IXP (all labs).
Studio / Studio WebThe tools where you build automations (called workflows or processes) by combining activities. Studio is the desktop tool, Studio Web runs in the browser.Lab 4: the lean workflow; Lab 3 approach A.
RobotThe runtime that executes a published automation, attended (next to a person) or unattended (on a server).Runs your Lab 4 workflow.
OrchestratorThe web application that manages robots, deploys automation packages, runs jobs and holds shared resources. Resources live in folders, which also control who can use them.Lab 4: folder and storage bucket for validation tasks.
Action CenterWhere people pick up and complete tasks that a robot creates, for example "check these extracted values". The robot pauses until the task is done, then resumes.Lab 4: validation tasks.
Document Understanding (DU)UiPath's framework and activities for processing documents: digitization, classification, extraction, validation and export.Classifiers (Lab 3), activities and Validation Station (Lab 4).
IXPUiPath's extraction service for unstructured data, with three capabilities: Communications data, Structured and semi-structured documents (DU models), and Unstructured and complex documents (generative, prompt-driven).Labs 1–4 use Unstructured and complex documents.

Document Understanding: the five steps every document goes through

Takeaway: whatever tool you use, a document goes digitize → classify → extract → validate → export. IXP replaces the extract step; the other steps still need a decision from you.

What it isThe DU framework's four fundamental capabilities – digitization, classification, extraction and validation – plus data consumption (exporting the result to the system that needs it).
What it doesDigitize: turn a file into machine-readable text and layout; OCR (optical character recognition) reads scanned pages and has its own confidence. Classify: decide the document type (and, for packets, the page range of each document). Extract: pull out the values you need. Validate: a person checks low-confidence or rule-failing values. Export: hand the data to Excel, a database or an ERP (enterprise resource planning) system.
When to useAs the mental model for any document project. Use the full framework (classification, splitting, several extractors, training) only when the process needs it. When not: for one document type extracted by IXP, a much shorter chain is enough (see Lean workflow).
How to use
  1. Ask: does every file hold exactly one document type? If yes, skip classification.
  2. Pick the extractor (in this workshop: an IXP model).
  3. Decide when a person must check the result (thresholds + business rules).
  4. Decide where the data goes.
Common mistakes
  • Assuming IXP extraction classifies or splits packets. The Unstructured and complex documents capability returns fields, not document types or boundaries.
  • Building the full framework "because that is how DU is done" when the process needs only extract + check + export.
  • Mixing up OCR confidence (how sure the text reader was) with extraction confidence (how sure the model was about a value).

IXP and its Unstructured and complex documents capability

Takeaway: when this workshop says "IXP", it means the Unstructured and complex documents capability: you define what to extract (the taxonomy) and describe it in words (instructions), and an LLM fills it in. You improve results by changing instructions or model settings, not by training.

What it isOne entry point in Automation Cloud for three extraction capabilities, chosen by data type: Communications data (emails, tickets), Structured and semi-structured documents (DU models), and Unstructured and complex documents (generative extraction). DU remains a standalone service that you can also reach through IXP.
What it doesThe Unstructured and complex documents capability reads the digitized document and returns your fields as structured output, each with a confidence at runtime. It handles free-form text, complex tables, high layout variation and several document types in one file without splitting.
When to useNew document projects with varying layouts, values that must be inferred, complex tables, or stacks of documents in one file. When not: if a specialized out-of-the-box DU model fits (for example invoices) or you need a model you can fine-tune and retrain, DU Modern or Classic can fit better. It doesn't classify or split packets, and it doesn't learn from your annotations.
How to use
  1. Open IXP in Automation Cloud and create a project with the Unstructured and complex documents capability.
  2. Upload a representative sample.
  3. Define the taxonomy and instructions, review predictions, measure.
  4. Publish a version and call it from a workflow or the DU API.
Common mistakes
  • Saying IXP "replaces" DU. DU stays a standalone service; IXP Unstructured and complex documents is one more extraction option.
  • Expecting the model to get better because you confirmed many values. It does not learn from annotations; your annotations only make the scores trustworthy.
  • Choosing the capability before looking at the documents. Use the docs' capability decision guide first.
What "LLM" and "prompt" mean here

An LLM (large language model) is an AI model that reads text and generates text. A prompt is the text you send it. In IXP you never write the full prompt yourself: your taxonomy, data types and instructions are assembled into the prompt for you, and the answer comes back already shaped into your fields.

Glossary

Keep this list open in a tab during the labs.

Project
The IXP container for one use case: uploaded documents, taxonomy, instructions, your annotations, scores and model versions.
Taxonomy
The extraction schema: field groups, fields, data types and instructions. In IXP it is both the prompt and the shape of the output.
Field group
A set of related fields, for example Statement Header or Account. It behaves like a table (fields are its columns) and can be returned once per occurrence in the document. Every field belongs to a group.
Field
One value to extract, such as Closing Balance, with a name, a data type and an instruction.
Data type / field type
What kind of value a field holds and how it is formatted. Pre-configured types include Exact Text, Inferred Text, Number, Date and Monetary Quantity; Boolean (true/false) is also available as a data type. You can create your own field types, for example a Choice type with a closed list of values.
Instructions
Plain-language descriptions at four levels: overall (whole project), field group, field and field type. Together they tell the model what to extract and where.
Prediction
A value the model extracted.
Annotation
A value you confirmed or corrected. It is the reference answer for scoring. It does not train the model.
Evaluation (Measure)
Comparing predictions with annotations to get precision, recall and F1 per field and field group, shown on the Measure page.
Confidence
A 0–1 estimate of how sure the model was about a value. For IXP it is returned per field at runtime. A signal, not proof of correctness.
OCR
Optical character recognition: reading text from scanned images. Part of digitization, with its own confidence score.
Digitization
Turning a file (native, scanned or mixed PDF, image) into machine-readable text and layout before extraction.
Model version
A published snapshot of the project configuration (taxonomy, instructions, model settings). You tag a version Staging or Production, and callers use the tag.
Validation Station
The review screen: document on one side, extracted values on the other, with confidence colours, so a person can confirm or correct.
Action Center
The place where people complete tasks created by robots, including validation tasks. The robot waits, then continues with the checked data.
Document Data
The variable that the Extract Document Data activity returns in Studio: field values plus extraction and OCR confidence per field.
HITL
Human in the loop: only risky items go to a person for review.
💬 "What is IXP, and how does it relate to the DU we already use?"

IXP is UiPath's umbrella for extraction. Its Unstructured and complex documents capability uses an LLM that you steer with instructions, so you can start without training data and handle layouts that vary a lot. DU is still there: its classifiers, Validation Station and activities are what you use around IXP to split packets, review results and run the process. Think of IXP as a new extractor that plugs into the DU way of working.

💡 Key takeaways
  • Every document project is digitize → classify → extract → validate → export. IXP does the extract step.
  • IXP Unstructured and complex documents extracts fields; it doesn't classify, split packets or learn from annotations.
  • Your taxonomy and instructions are the prompt. Better instructions, not more annotations, give better results.
  • Confidence exists at runtime only and is a signal, not a guarantee.
